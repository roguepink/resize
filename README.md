# 写真・動画リサイズ

写真も動画も、えらぶだけで ぐっと小さくするアプリ。上の「📷 写真 / 🎬 動画」で切り替える。
小さくしたものは、そのまま **LINE などで送る**か、**保存**できる。
スマホ(ブラウザ)の中だけで処理し、どこにも送らない。写真の位置情報(どこで撮ったか)も自動で消える。

**使う: https://roguepink.github.io/resize/**(動画の方を開く: `https://roguepink.github.io/resize/#video`)

## 使い方

- **📷 写真**: 重さをえらぶ(ふつう = 1枚 200〜300KB が標準。小さめ 約100KB / 大きめ 約500KB)→「写真をえらぶ」で何枚でも → 「LINEなどで送る」か「まとめて保存」
- **🎬 動画**: 割合をえらぶ(25% = 重さを4分の1に、が標準。50% / 10% も)→「動画をえらぶ」で1本 →「小さくする」→「LINEなどで送る」か「保存する」
  - **動画と同じ時間がかかる**(1分の動画なら 約1分)。終わるまで画面をそのままに。止まったら「つづきから」
- 小さくしている最中は、写真と動画を切り替えられない(動画は見えていないと止まることがあるため)
- 前回使った方(写真 / 動画)で開く

## LINE で送る・ホーム画面に入れる

- 上のアドレスを LINE に貼れば、タイトルと絵つきの紹介が出る。タップするとすぐ使える
  - 前に「写真リサイズ」として送ったことがあると、LINE が古い紹介を覚えていることがある。`https://roguepink.github.io/resize/?v=3` のように末尾に印をつけて送ると新しく見に行きやすい
- **LINE の中で開いたときは うまく動かないことがあり、ホーム画面にも入れられない。**メニューから「Safari で開く」(iPhone)/「他のアプリで開く」→ Chrome(Android)を選ぶ
  - iPhone(Safari): 共有ボタン →「ホーム画面に追加」 / Android(Chrome): メニュー(︙)→「アプリをインストール」
- 入れたあとは全画面で起動。一度開けば電波がなくても使える

## 中身・しくみ

- `index.html` 1枚で完結(外部ライブラリなし)。`manifest.webmanifest` と `sw.js` でホーム画面・オフライン対応
- 写真と動画は、それぞれ別の囲み(関数)の中にあり、部品の名前は `p_…`(写真)/ `v_…`(動画)。切り替えは最後の「写真 / 動画 の切り替え」
- 2026-10-13 に、写真リサイズ(このリポジトリ)と動画リサイズ(`roguepink/dogaresize`)を1つにまとめた。まとめ方は `_check/merge.py`(Git には入れていない作業用)。**これからは この `index.html` を直接直す**
- 旧アドレス `roguepink.github.io/dogaresize/` は、ここの動画の方へ自動で飛ぶ

### 写真

- できあがりの重さが目標(ふつう 200〜300KB)に入るまで、JPEG の画質 → 大きさ の順に自動調整する(`nextStep()`)。縮小は半分ずつ段階的に行う。もともと小さい JPEG はそのまま

### 動画

- 動画を再生しながら、小さい絵(canvas)に描き直して `MediaRecorder` で録画し直す。だから **動画と同じ時間がかかる**
- 割合(`CONFIG.MODES` の `pct`)から、もとの動画の 1秒あたりのデータ量 × 割合 を目標にする(`plan()`)。絵の大きさ(1080 / 720 / 480 / 360)は「1画素あたりのデータ量が足りる いちばん大きいもの」を自動で選ぶ。音は 96kbps 固定(64k だと mp4 の音の圧縮が失敗した)
- **できあがりを組み直す**(`remuxMp4()` / `fixWebmDuration()`): ブラウザが作る mp4 は細切れ(fragmented)で長さの情報がなく、Android や LINE が最初の数秒しか読めなかった(2026-10-13 ノブさんの Android)。全コマの表を持つ ふつうの mp4 に組み直す。webm は長さを書き足す。組み直せなかったときは「未整形」と出る
- できあがりの形式はブラウザしだい: iPhone の Safari・Mac の Chrome は mp4、Android の Chrome は mp4 か webm
- 失敗したら: 録画の形式が原因なら別の形式で自動でやり直す(2回まで)。失敗の詳しい情報を画面に出す(スクショで原因が分かる)
- ほかのアプリに切り替える・画面が消えると いったん止まり、戻ると続ける(自動で続かなければ「つづきから」ボタン)。wake lock で画面が消えにくくする

## 確認用

- アドレスの末尾に `#play` で、作ったテスト写真3枚で動作確認(写真)。`#play-video` で、その場で作った3秒の動画で動作確認(動画。自動再生を許したブラウザのみ)
- `_check/` に Playwright のテスト(Git に入れない): `tabs.py`(写真・切り替え)/ `e2e.py`(動画3通り)/ `pause.py`(止めて再開)/ `fallback.py`(形式の切り替え)/ `webm.py`

## 直して公開するとき

- `main` に push すれば公開される(GitHub Pages)。電波のある人は、**次に開いたとき**に新しい版になる(`sw.js` は まずネットで最新を取りにいく)
- `sw.js` の `VERSION` を上げるのは、覚えるファイル(`FILES`)や `manifest.webmanifest` を変えたときだけ
- Chrome が「すでにインストールされています」と言って入れられないときは、`manifest.webmanifest` の `id` を新しい値に変える(Chrome は `id` でアプリを見分ける。2026-10-12 に Android で起きて `./?app=resize-2` にした)。**今の `id` のままなら、前に写真リサイズを入れた人のアイコンが そのまま新しい版になる**
